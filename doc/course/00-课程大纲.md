## 写在前面:为什么这门课叫 Harness 101

> **模型是大脑,Harness 是身体、工作台和安全边界。**

Harness 是 2025–2026 年 AI 工程师岗位描述里出现频率上升最快的词之一(DeepSeek、Anthropic、OpenAI、智谱、阿里、字节等团队都在招 Harness 工程师),但它不是一个库、不是一个框架,而是一类**系统设计**。

这门课要回答的核心问题只有一个:

> **当模型已经足够聪明,为什么 Demo Agent 还是不能上线?**

答案全在模型外面:
- 上下文怎么组织才不会污染注意力
- 工具怎么设计才不会让模型选错
- 状态怎么管理才不会长任务中途丢上下文
- 危险动作怎么拦截才不会"模型一句'我觉得可以'就退款"
- 出问题怎么回放、怎么定位、怎么归因

把这一整套工程系统讲清楚、做出来,就是 Agent Harness 101。

## 详细模块大纲

### M0: 导论与心智模型 (Week 1, 2 学时)

> **核心问题**:什么是 Harness?为什么模型够了还不够?

#### 学习目标

完成本模块后,你能:
- 用一句话解释「模型 + Harness = Agent」的心智模型
- 区分 Demo Agent 和 Production Agent 的 10 个真实差距
- 用自己的话解释 Harness 6 层架构(每层职责、层间依赖、典型反模式)
- 区分 Harness / MCP / Workflow / Context Engineering
- 写一个 30 行的最简 Agent

#### 课程内容

- **0.1 AI Agent 的演化**:从 Chatbot → Function Calling → Coding Agent → 多 Agent 协作
- **0.2 一个朴素 Agent 循环的代码实现**:20–30 行 Python,3 个工具,看懂就跑通
- **0.3 Demo 变生产时遇到的 10 个真实问题**:
  - 能读哪些文件?能不能改文件?能不能执行任意 shell?
  - 超时怎么办?上下文爆了怎么办?
  - 改错了怎么回滚?连续失败 3 次还要不要继续?
  - 事后怎么审计?为什么做出某个修改?
- **0.4 Harness 的 6 层架构**:
  1. 上下文管理(Context Engineering)
  2. 工具管理(Tool Registry)
  3. 执行环境(Execution Sandbox)
  4. 状态与记忆(State & Memory)
  5. 验证与评估(Verification & Eval)
  6. 观测与审计(Observability & Audit)
- **0.5 Harness vs MCP vs Workflow vs Context Engineering**:
  - MCP = 工具怎么接进来
  - Context Engineering = 材料怎么放到模型面前
  - Workflow = 确定流程怎么走
  - Harness = 模型外面的整体运行和控制系统
- **0.6 课程地图**:16 周我们要走的路径
- **0.7 工业级 Harness 实例(开篇导览):DeepSeek Harness(DSH)**
  - 2026-08-13 DeepSeek 开源 DSH(MIT,GitHub `deepseek-ai/deepseek-harness`),口号「Everything is a Plugin」
  - 5 天内 13.5 万星,GitHub 史上最快涨星曲线之一
  - 核心架构:模型/工具/会话/沙箱/UI 全是 Cordis 插件,Agent 循环本身也是插件
  - 4 种运行模式:标准 / PTC(程序化工具调用)/ 极简(评测台)/ 创造(运行时自修改)
  - 仅追加会话日志(append-only session log)作为运行时不变式
  - **本课视角**:DSH 是 6 层 Harness 的**最严谨开源实现**,M5 会有专门一节课深读它
  - 看一眼就跑:`npx @deepseek-ai/dsh web` → http://127.0.0.1:3080

#### 实践任务

- 🎯 **任务 0.1**: 用 30 行 Python 写一个最简 Agent(读文件 + 搜索 + 跑命令 3 工具)
- 🎯 **任务 0.2(加分)**: 跑一遍 `npx @deepseek-ai/dsh web`,在 Web UI 里让 DSH 读一个项目目录,对比「30 行最简 Agent」和 DSH 跑同样任务时的差距

### M1: Python 工程化基座 (Week 2–3, 16 学时)

> **核心问题**:怎么写出 Harness 底层需要的 Python?
> **v1.2 注**:12h 装不下三件事,扩到 16h;Lesson 1.3 增「模型路由 / fallback / 限流」,这是 M6 成本与限流的前置基础。

#### 学习目标

- 熟练使用 `asyncio` / `await` 写并发代码
- 用 Pydantic 做严格的输入/输出 schema 校验
- 理解 LLM 的 Streaming / Function Calling JSON 协议
- 独立封装一个「LLM 客户端 SDK」,内含模型路由、限流、fallback 三件套
- 区分同步/异步/并发/并行,知道 Harness 哪一层适合用哪种并发模型

#### 课程内容

**Lesson 1.1 — 异步编程 (4h)**
- `asyncio` 核心:event loop / coroutine / task / gather / semaphore
- `aiohttp` 异步 HTTP
- 并发 vs 并行:Harness 为啥需要异步(尤其工具并发调用 + 多子 Agent 调度)
- 限流原语:`asyncio.Semaphore` / token bucket
- 实操:用 asyncio 并发调用 10 次 LLM,对比同步耗时;用 Semaphore 限制 QPS

**Lesson 1.2 — 类型系统与数据校验 (4h)**
- Python Type Hints 全家福:`Optional` / `Union` / `Literal` / `TypedDict` / `Protocol`
- Pydantic v2 核心:`BaseModel` / `Field` / `validator` / `model_dump` / `discriminated_union`
- LLM 输出校验:Harness 必须做 JSON schema 校验的原因
- 实操:用 Pydantic 校验 Function Calling 的参数 + 用 discriminated_union 处理多工具调用

**Lesson 1.3 — LLM 客户端 SDK 实战 (5h)**
- OpenAI / Anthropic / Ollama 三家 SDK 对比(协议层、错误码、限流策略)
- Streaming 输出解析(SSE 协议)
- Function Calling 的 JSON 协议
- 错误处理:rate limit / timeout / 4xx / 5xx
- **模型路由**:按任务类型 / 成本预算 / 延迟 SLA 选模型(便宜模型走大量,贵模型走关键决策)
- **Fallback 链**:主模型失败 → 备胎模型 → 本地小模型 → 报错
- **客户端级限流**:按 provider 分别维护 token bucket
- 实操:封装一个支持 3 家厂商、可切换、流式输出、带路由 + fallback + 限流的 LLM Client

**Lesson 1.4 — 调试与可观测性基线 (3h)** ⭐ v1.2 新增
- 结构化日志(`structlog`):每条 LLM 调用打 log(模型 / 延迟 / token / 错误)
- 简单 metrics 计数器(内存版即可):QPS / 错误率 / 平均延迟
- `pdb` / `icecream` 调试技巧:异步代码断点
- 实操:为 M1.3 的 LLM Client 接入结构化日志,跑 100 次请求生成第一份 metrics 报告

#### Module 项目: **M1-LLMClient**

- 目标:实现一个生产级 LLM 客户端
- 接口:`chat(messages, tools) -> Response` + `chat_stream(messages) -> Iterator[Delta]` + 路由 / fallback / 限流
- 验收:
  - ✅ 能切 3 家模型
  - ✅ 能处理 4xx/5xx(可重试 vs 不可重试分类)
  - ✅ 能输出 stream
  - ✅ 能用 Pydantic 校验 tool call
  - ✅ ⭐ 主模型失败自动 fallback 到备胎
  - ✅ ⭐ 100 次压测下 QPS 不超配置上限
  - ✅ ⭐ 有结构化日志可看每次调用

#### 评估

- 代码 review(异步写法是否正确、Pydantic 用法是否规范)
- 单元测试覆盖率 ≥ 70%
- 文档:README + 简单 demo

### M2: LLM 与上下文工程 (Week 4–5, 16 学时)

> **核心问题**:怎么管理模型"看到的世界"?

#### 学习目标

- 理解 LLM 的输入边界:Token 限制、注意力衰减、上下文腐烂
- 实现 3 种上下文压缩策略
- 设计短期记忆 / 长期记忆 / 工作记忆的分层
- 防御 prompt injection

#### 课程内容

**Lesson 2.1 — Token 经济学 (3h)**
- Token 是什么、怎么数、怎么算钱
- 上下文窗口的真实限制(不只是 8K/128K,还有注意力衰减)
- "上下文腐烂"(Context Rot)现象
- 实操:用 `tiktoken` 计数,用日志分析你过去 1 周的 token 消耗

**Lesson 2.2 — 上下文压缩 3 策略 (6h)**
- **截断策略**:滑动窗口、头尾保留
- **摘要策略**:用 LLM 把长历史压缩成短摘要
- **引用策略**:工具结果只给"指针"不全文塞入
- 实操:实现 3 种压缩器,在同一份长对话上对比效果

**Lesson 2.3 — 记忆分层设计 (4h)**
- 工作记忆(当前任务上下文)
- 短期记忆(本次会话历史)
- 长期记忆(跨会话持久化:SQLite/JSON/向量库)
- 实操:用 SQLite + FTS5 实现可检索的长期记忆

**Lesson 2.4 — Prompt Injection 防御 (3h)**
- 直接注入 vs 间接注入
- 来源标注(content provenance)
- 工具结果与系统指令的隔离
- 实操:构造 5 个注入样本,验证你的防御方案

#### Module 项目: **M2-ContextEngine**

- 目标:实现一个上下文管理器
- 功能:压缩 / 摘要 / 引用 / 注入检测
- 验收(⛳ v1.2 修正):**在 100K token 长会话上能稳定控制窗口在 8K 以内,任务相关召回率 ≥ 90%**(对比基线:无压缩的 100K 直接灌入)。「无信息丢失」是伪命题,改为「业务目标可接受的召回」

#### 评估

- 压力测试(⛳ v1.2 修正):100K token 长会话不爆,生成式 QA 任务上召回 ≥ 90%
- 注入测试:5 个样本至少拦住 4 个
- 性能:压缩延迟 < 500ms / 步

### M3: 工具与 MCP (Week 6–7, 12 学时)

> **核心问题**:怎么把外部世界接进来?

#### 学习目标

- 掌握 Function Calling 的底层 JSON 协议
- 学会把"内部系统 + 第三方 API"封装成 Tools
- 理解 MCP 协议的设计哲学
- 维护一个工具注册表,实现"按需加载"

#### 课程内容

**Lesson 3.1 — Tool 设计原则 (4h)**
- 工具描述就是 prompt:写好 docstring 的 4 个要素
- 参数 schema:必填/可选/枚举/边界
- 工具粒度:细粒度 vs 粗粒度的 tradeoff
- 实操:把 5 个日常 API(查天气/查股票/发邮件/读文件/搜索)封装成 Tool

**Lesson 3.2 — Function Calling 协议深挖 (4h)**
- OpenAI / Anthropic 的 tool_call JSON 格式差异
- 多轮 tool_call 的状态管理
- 工具结果回灌上下文的最佳实践
- 实操:支持多 tool 并行调用(tool_choice=auto + 多 tool_calls)

**Lesson 3.3 — MCP 协议入门 (6h)** ⛳ v1.2:MCP 4h → 6h
- MCP 是什么:`MCP = Agent TCP/IP`,为什么 2026 年它是事实标准
- MCP Server / Client / Resource / Prompt / Tool 五要素
- **传输层 2 种模式** ⭐ v1.2 新增:
  - **stdio**:本地子进程,适合本地工具(读文件、跑命令)
  - **HTTP/SSE**:远程服务,适合云端工具(企业 API、SaaS)
- 实战 1:用 Python SDK 写一个 stdio MCP Server,接 Claude Desktop 验证
- 实战 2:用 Python SDK 写一个 HTTP/SSE MCP Server,跨进程调用
- 工具注册表:动态加载、权限过滤、版本管理
- **MCP vs 直接 Function Calling**:什么时候用 MCP,什么时候直接 tool_call 就够

#### Module 项目: **M3-ToolKit**

- 目标:实现 5 个生产级工具 + 一个工具注册表 + 1 个 MCP Server
- 工具集:read_file / search_code / run_cmd / http_get / sql_query
- MCP Server:把 1-2 个工具通过 stdio 协议暴露,接 Claude Desktop 验证 ⭐ v1.2 新增验收项
- 注册表:支持按任务动态启用/禁用工具

#### 课程内容(7 个 lesson:M5.0 工业级对标 + M5.1–5.6 逐层实战)

**Lesson 5.0 — 工业级对标:DeepSeek Harness (DSH) 深度案例 (4h)**

> 在动手造 6 层之前,先用 4 小时读一份**真实在跑、5 天 13.5 万星**的工业级 Harness,把"应该做成什么样"在心里立个标杆。

- **5.0.1 30 分钟看明白 DSH 是什么**:读 `deepseek-ai/deepseek-harness` README + 仓库结构(453K TypeScript,219 个 workspace 包,vendored Cordis 4.x-rc.7 + 18 个本地 patch)
- **5.0.2 60 分钟拆 Cordis 内核**:
  - 5 个核心概念:Context(共享容器)/ Plugin(最小单元)/ Inject(依赖声明)/ Effect(带逆函数的副作用)/ Service(插件间通信)
  - 对照 Spring IoC 看 Cordis 的"AI 场景适配":4 种事件分发(观察者 / 中间件 Waterfall / 并行 / 串行)
  - 形式化类型:`Γ → Γ × (Γ → Γ)`,副作用 + 逆函数
- **5.0.3 60 分钟读 5 个定理**:
  - **保持性**:组件不会污染上下文 → 隔离域(realm)
  - **时间可组合性**:卸载不留残余 → 逆函数累加器
  - **空间可组合性**:依赖变化不雪崩 → 反应式余效应
  - **进展性**:死锁能被打破 → UNLOADING 中间态
  - **汇流性**:静态推理 = 动态历史 → 推理动态系统当静态系统推理(分量最重)
  - 配套论文:《A Programming Paradigm for Spatiotemporal Composability》(Yifan Shi / Wei Zhang / Tianyi Cui,北大+DeepSeek,2026-08 预印本,80 页 20+ 定理)
- **5.0.4 30 分钟看 4 种模式**:
  - **标准**:全工具
  - **PTC(Programmatic Tool Calling)**:模型生成 TS 代码,中间数据留运行环境,只把最终结果回灌上下文 → 省 token
  - **极简**:只两个工具(bash + str_replace_editor)→ 公平评测脚手架
  - **创造**:让 Agent 自己挂载 / 卸载临时插件(等同 shell 权限,默认关)
- **5.0.5 30 分钟看 3 个工程不变式**:
  - **Append-only session log**:模型看到的每条消息都能从日志字节级重建(`packages/core/agent-loop/src/invariant.ts` 强制断言)
  - **Fail-closed sandbox**:沙箱后端拿不到直接 `SANDBOX_UNAVAILABLE` 拒绝执行,绝不裸奔
  - **配置层组合**:Profile + Bundle + Patch 三层叠加,任意覆盖,不依赖加载顺序
- 实操:跑通 DSH,Web UI 里用极简模式对比 LangGraph Agent 同任务表现;读 100 行 `vendor/cordis/bin.js` 启动器源码

  - ✅ **无资源泄漏**:`docker stats` 观察 1 小时,内存稳定(±10% 波动),文件句柄数稳定
  - ✅ **故障注入**测试:手动 kill -9 主进程,systemd 拉起后能接续上次任务
  - (24×7 真生产不在 101 课程目标内,那是 201 课程的事)

## 常见问题 FAQ

### Q1:我没有 AI 背景,能学这门课吗?

**A**:能。课程从 M1 Python 工程化开始,不会涉及模型训练/微调,只用 API。所有 AI 概念都会从"工程视角"重新讲一遍。

### Q2:学完能找到工作吗?

**A**:诚实说,**课程本身不保证 Offer**。但 Capstone 是一个能上简历的项目,完成 M0–M5 后你至少能:
- 在面试中讲清楚 Harness 6 层
- 用 LangGraph 写一个 Agent
- 设计一个 Eval 集

这些已经是 2026 年 AI 工程师岗位的**面试高频题**。配合投递策略,概率比"只学过 prompt"高得多。

### Q3:必须用 OpenAI 吗?能不能用国产模型?

**A**:可以。课程默认 OpenAI / Anthropic,所有 LLM Client 抽象成统一接口。Capstone 推荐至少接 3 家(OpenAI / Anthropic / Ollama 或 Qwen/DeepSeek 本地)。

### Q4:Capstone 一定要发到 GitHub 吗?

**A**:建议发。完成 Capstone 后,写一份高质量 README + 一段 5 分钟演示视频,这是 2026 年最值钱的简历素材。

### Q5:学完下一步学什么?

**A**:三条路:
- **深挖工程**:MCP 协议实现、长期记忆优化、多 Agent 协作
- **深挖应用**:选一个垂直领域(代码 / 客服 / 数据分析 / 浏览器),做行业级 Agent
- **深挖模型**:转向 LLM 训练 / 微调 / RLHF,需要补数学和 ML 基础

### Q6:Harness 工程师和 Prompt 工程师、Agent 工程师有什么区别?

**A**:
- **Prompt 工程师**:优化模型输入
- **Agent 工程师**:用现有框架(LangChain / LangGraph)拼装 Agent
- **Harness 工程师**:设计 Agent 之外的整套运行系统

后两者的边界是模糊的,但**Harness 工程师更强调"系统设计"**,而不是"框架使用"。

### Q7:这门课和网上免费的 LangChain 教程有什么区别?

**A**:
- 网上教程:教你怎么**用** LangChain
- 这门课:教你怎么**设计一个 LangChain 不能直接给你的系统**

具体来说,网上很少有课程系统讲:
- 6 层 Harness 怎么解耦
- 状态机怎么做
- Sandbox 怎么实现
- HITL 怎么嵌入
- Eval 怎么自动化

这些是"上线"和"demo"的真正差距。

### Q8:我没时间做 Capstone 怎么办?

**A**:退一步,完成 8 个 Module 项目也可以拿到结课证明。但 Capstone 是**真正体现能力**的部分,强烈建议至少花 24 小时认真做。

## 致学生

如果你正在读这份大纲,你大概率已经意识到:

> **AI 时代真正的差距,不在模型,在 Harness。**

模型会越来越强、越来越便宜。  
但**怎么让模型安全、可靠、可审计地做事**,这个能力不会自动到来。

学完这门课,你不会成为"最会调 prompt 的人",但你会成为:
- 能独立设计 6 层 Harness 的人
- 能用工程方法论解决 Agent 可靠性问题的人
- 能讲清楚"为什么这个 Agent 不能上线 / 怎么改"的人

这,就是 2026 年 AI 工程师的核心竞争力。

**欢迎来到 Harness 的世界。**
